# Data sources and attribution

## Source calibration data

The calibration source is **Qiskit Calibration Drift**, maintained by `phanerozoic` on Hugging Face Datasets:

- Dataset: https://huggingface.co/datasets/phanerozoic/qiskit-calibration-drift
- Pinned revision: `bfaaec7ee00a091b1710153e251f4c69e1ac9254`
- Source file: `data/train-00000-of-00001.parquet`
- Dataset license: CC BY 4.0, as stated on the dataset card
- Original calibration properties: IBM Quantum backend properties

The dataset records IBM-derived backend calibration properties with observation timestamps, calibration timestamps, and component calibration ages. The extraction in `src/extract_calibration.py` selects the CZ-error and readout-error families for `ibm_fez`, `ibm_kingston`, and `ibm_marrakesh`, filters invalid/failure-ceiling values, canonicalizes undirected CZ pairs, and aggregates each backend/observation/property-family group using median, 90th percentile, component count, and calibration-age summaries.

The compact output, `data/ibm_heron_calibration_snapshots.csv`, is a derived selection and aggregation of the source. Retain this attribution and the CC BY 4.0 terms when redistributing that data. The source dataset also contains `ibm_torino`; this study does not use that backend.

## Generated workload data

The workflow DAGs, arrival processes, gate/readout operation counts, task durations, deadlines, and error budgets are generated by `src/simulate.py` from fixed seeds. They are synthetic experiment inputs, not observations from IBM or an HPC workload trace. `results/workflow_metrics.csv` contains simulator outputs, not hardware measurements.
